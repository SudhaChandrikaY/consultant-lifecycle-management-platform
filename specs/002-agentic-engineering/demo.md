# Demonstrations: Each Component Once

**Feature**: `002-agentic-engineering`, User Story 6, 2026-10-03. Every request ran against
**existing** CLMP code. No application file was changed.

| Component | Example request | Result | What it demonstrated |
|-----------|-----------------|--------|----------------------|
| `clmp-codebase-analyst` (subagent) | "Inspect the existing Consultants search functionality and tell us which files and modules are involved." | It traced `GET /api/consultants` → `ConsultantController` → `ConsultantFilter` / `ConsultantSpecifications.matching` + `scopeFor` → repository, plus the frontend `ConsultantListPage`, `UrlSearchField`, `useUrlFilters`, and the tests (`US2ConsultantProfileIT.as2_4_searchAndFilters`, `listNameSearch.test.tsx`, …). It found real gaps: `%`/`_` in `q` are not escaped, and there is no unit test for `matching`. | A **subagent** works in its own context with read-only tools (`Read`, `Grep`, `Glob`), returns a structured report, and changes nothing. |
| `clmp-code-reviewer` (subagent) | "Review commit b46385e (the name-search fix) and report any concerns." | Verdict **approve**. It confirmed the root cause (an effect keyed on a new `filters` object each render) and that the new test would fail on the old code. Findings: R2 minor (a new placeholder on the Recruiters box, slightly outside scope), R3 minor (the tests don't cite requirements), plus two notes. | An **independent** reviewer judges the code, not the author's explanation. It uses the project rules from the preloaded skills, assigns severities, and doesn't edit. |
| `clmp-test-validator` (subagent) | "Run one small targeted validation for that search fix." | `npm run typecheck` passed. The two Vitest files passed (2 files, 11 tests); the WSL timeout didn't occur this time. It ran no full suites, and therefore declined to say `ready` without the full frontend tests and build. | The validator **chooses and runs** checks within limits and is honest about what it did not run. |
| `/clmp-change-workflow` (skill) | "Explain how you would approach a small CLMP change, e.g. show the recruiter's team on the consultant list." | 1. Scope: this changes 001 FR-023 (list columns), so it needs a spec amendment, not a trivial fix. 2. Ask the analyst. 3. Add `teamName` to the `ConsultantListItem` DTO, mapped in the service, with the scope unchanged. 4. Add a `DataTable` column. 5. Tests in the US2 IT and the frontend. 6. Reviewer → readiness. | A **skill** is reusable instructions loaded into the *current* conversation. It shapes how the main agent works; it is not a separate worker. |
| `/clmp-release-readiness` (skill) | "Which checks would you choose for a small frontend-only change?" | Frontend: `npm run typecheck`, `npm test -- --run`, `npm run build`. Skip the backend `verify`, the authorization tests, and perf. A WSL Vitest timeout counts as an environment blocker. It mapped the results to the constitution's Quality Gates. | The same skill text is also **preloaded by the validator agent**, so the main agent and the subagent apply identical rules. |
| GitHub MCP (`.mcp.json`) | "Use the github tools to read PR #1 and summarize what it did." | **Succeeded** in a fresh session after the developer set `CLMP_GITHUB_PAT` and approved the server. Only read tools were offered (`get_*`, `list_*`, `search_*`, `pull_request_read`). Claude called `pull_request_read` (`get`, `get_commits`, `get_files`) and summarized PR #1: the merged CLMP MVP (14 commits, 275 files), user stories US1–US8 (sign-in and roles, consultants, recruiters, marketing, submissions, placements, dashboard, reports) plus the authorization, exposure, and concurrency tests. Nothing was modified on GitHub. | **MCP** connects Claude to an external system (GitHub) through tools. It is read-only here, at both the endpoint and the token level, and no secret is in the repository. |

**In one line**: subagents are separate workers with their own context and tools; skills are
reusable instructions for whoever loads them; MCP gives agents tools that reach outside the
repository.
